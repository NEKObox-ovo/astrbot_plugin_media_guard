# 媒体发送守卫

> 修掉那些「图片发不出去」「文件资源不存在」「格式错误」的老问题。

各平台适配器在处理媒体消息段时，失败原因其实很集中：远程 URL 平台拉不到、文件早就失效、体积超出限制。结果往往是消息直接消失，或者把一串 Python 异常甩到聊天里。

这个插件在发送动作发生前做一轮处理，把能救的救回来。

## 做了什么

| 问题 | 处理方式 |
| --- | --- |
| KOOK 报 `资源不存在` / `40000` | 发送前把远程 URL 下载到本地，走本地上传通道 |
| 图片几 MB 甚至更大 | 自动缩到 2048px 内、转 JPEG（quality 85） |
| 文件路径失效 | 记录日志并降级为提示文本，不抛异常 |
| 发送时抛出未捕获异常 | 兜底发一条说明，而不是让消息静默消失 |

## 支持的平台

- KOOK
- QQ 官方机器人
- OneBot（aiocqhttp）

插件启动时包装上述适配器的 `send()`，卸载时自动还原，不修改 AstrBot 本体文件。

## 配置

| 项 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | 开 | 总开关 |
| `localize_remote` | 开 | 远程资源先落本地，KOOK 必须开 |
| `compress_image` | 开 | 超大图片压缩 |
| `image_limit_mb` | 2.0 | 超过才压缩 |
| `download_limit_mb` | 30.0 | 下载上限，防止吃满内存 |

## 指令

```
/mediaguard
```

查看当前状态、已接管的适配器、各阈值。

## 注意

- 临时文件写在 `data/temp/media_guard/`，启动时清理 6 小时前的文件
- 下载大文件会增加耗时，属于用时间换成功率
- 如果平台本身拒绝该格式（比如把 HTML 错误页存成 `.mp3`），插件救不回来，只会给出明确日志
